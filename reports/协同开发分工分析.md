## 2. 冲突面地图（并行开发的雷区）

### 🔴 高冲突（全局改动，需主线串行或提前冻结接口）
| 文件/区域 | 冲突原因 | 协调策略 |
|---|---|---|
| `aurora-core/src/event_bus/layered.rs` | AppEvent 枚举加变体 = 全投影编译错误 | 接口冻结制：新事件变体由主线一次加入，分支 rebase |
| `aurora-core/src/app_core.rs` | 服务组装/构造注入点 | 只允许主线改；其他 agent 提 trait + 拼装提案 |
| `aurora-core/src/traits/*` | 全局 trait 面（加方法=全实现体错误） | trait 变更走主线 review 后合并 |
| `crates/mobile-ffi/src/lib.rs` | uniffi 桥面（DK-07/13/15 都加方法） | 方法追加型冲突小；结构变更串行 |

### 🟡 中冲突（同目录新文件，rebase 可解）
- `aurora-core/src/l2_engines/`——多投影并存（search/graph/task/sync projection 各一个文件），**新文件+独立注册**即无冲突
- `entity/`+`migration/`——数据库迁移序列号必须全局递增（编号分配制）

### 🟢 低冲突（独占 crate/app，物理隔离）
- aurora-sync（DK-08）、aurora-ai（DK-10）、aurora-plugin（DK-14）、apps/desktop（DK-11）、apps/mobile TS 层（DK-15 前端）

## 3. 四 Agent 工作流划分（建议）

> 原则：**每个 agent 一个独占文件集（CODEOWNERS 语义）**；跨边界需求只提 issue/接口提案，不动他人文件。

### WF-Alpha（主线集成 + 安全，≈ 当前会话）
- **范围**：`aurora-security/**`、`aurora-core/src/l2_engines/search_projection.rs`、`traits/search_backend.rs`、CI 配置、`aurora-bootstrap`
- **任务**：DK-07 主体（加密落库链路、Private 工作区索引销毁、AI 拦截、ML-KEM 互操作审计）
- **特权**：唯一可改 AppEvent / traits / app_core 的 agent（接口冻结人）

### WF-Bravo（同步，≈45 人日起步即并行）
- **范围**：`aurora-sync/**`（独占）+ 只读依赖 traits
- **任务**：DK-08 全部——三适配器覆写 `recv_update`/`sync_version`（当前默认实现返回空，增量同步从未真实发生）、SyncRouter 四路选路、CRDT 冲突→`.conflict-{ts}.md`、Wi-Fi 同步开关、分片续传
- **交付方式**：新适配器文件 + trait 实现体，**不改 traits**（需要新接口时提给 Alpha）

### WF-Charlie（AI + 插件，≈95 人日）
- **范围**：`aurora-ai/**`、`aurora-plugin/**`（双独占）
- **任务**：DK-10（AI 液化与 Agent）+ DK-14（插件生态 manifest/加载器/权限模型）
- **注意**：DK-07 DoD「Private 工作区 AI 请求被阻止」的**拦截点在 aurora-ai 请求入口**——接口设计由 Alpha 给出（工作区加密策略查询 trait），Charlie 实现

### WF-Delta（桌面 + 前端，≈135 人日）
- **范围**：`apps/desktop/**`、`apps/web/**`、`apps/mobile/src/**`（TS 层独占；不碰 mobile-ffi Rust）
- **任务**：DK-11 画布 → DK-09 迁移向导 UI → DK-15 移动端完善
- **注意**：mobile 桥方法（mobile-ffi lib.rs + MainActivity.java）改动走 Alpha 的桥面队列

### 串行依赖（并行期结束后的接力）
DK-12 结构化数据（migration 编号占用，需 Alpha 协调）→ DK-13 协作（等 DK-08 合入）→ DK-17 备份 → DK-18 收尾。

## 4. Git 协作规约（防提交冲突）

1. **分支模型**：`main` 保护（branch protection 已开）；每个 WF 一条常驻集成分支 `wf/<name>`（如 `wf/bravo-sync`），从 main 切出，**每日 rebase main**
2. **推送节奏**：WF 分支内自由提交（小步快跑）；**集成时**由 Alpha 按序 merge 到 main（顺序：Bravo → Charlie → Delta，Alpha 最后收尾），单次 merge 前跑全量 CI
3. **文件锁约定**：CODEOWNERS 文件落地后，CI 加 paths-filter 检查——越界文件变更的 PR/merge 自动打回（可选，初期靠约定）
4. **迁移编号分配制**：`migration/` 新文件编号向 Alpha 领取（避免 seq 冲突）
5. **接口冻结窗口**：AppEvent/traits 变更集中每周一由 Alpha 批量合入，各 WF 当日 rebase——把编译错误集中到可预期时间
6. **CI 资源**：全量 CI ~10 分钟，merge 队列串行化；WF 分支只跑触达 crate 的 per-crate check（paths-filter 提速）
