# DK-17 L2 跨插件授权设计稿 · share 语义（2026-10-16 随 16.1 修复派发）

**出稿**: Alpha 2026-10-15 ｜ **Assignee**: Bravo ｜ **Estimate**: M ｜ **依赖**: DK-16 L1（namespace 隔离已落地）+DK-16.1（id 禁 `:` 堵口）｜ **Estimate 依据**: 跨插件面涉及 manifest 扩展+授权治理+e2e 双插件编排

## 一、定性

L1 把命名空间隔离为默认（一插件一空间）；L2 回答"**合法的跨空间如何发生**"——显式授权替代隔离穿透（A-4 逃逸的反面：不给暗道，给明门）。

## 二、设计

### 2.1 share 原语（宿主特权面）

- 新增 `HostFunction::Share`：`share(doc_id, to_plugin)`——**仅本命名空间内的键可分享**（前缀校验先行，与 L1 同 guard 面），目标插件获对该键的**只读映射**
- 授权记录：宿主侧 `shares: HashMap<(from_plugin, doc_id), to_plugin>`（可撤销 revoke）——**不入 guest 可见面**（guest 只知"能读"，不知授权图谱）
- 目标插件读取路径：读 `to_plugin` 视角下**不属于自己的键**仅当 shares 命中——L1 guard 的 read 分支增加 shares 豁免检查（命中→放行，未命中→namespace-denied 不变）

### 2.2 manifest 面

- 目标插件**无需预声明**（授权是运行时宿主动作）——但新增可选 manifest 字段 `accept_share: bool`（缺省 false=不接受任何分享，fail-closed 默认）——**最小暴露面**：插件显式 opt-in 才可能被分享
- 15c 徽章：`accept_share` 展示为"可接收分享"徽章（中性色，非警示——非能力项，数据流偏好）

### 2.3 A-1/A-5 随卡收口

- **A-1（pull_output 调用方鉴权）**：本卡宿主特权面扩容（Share 亦是），统一在 `call_host_function` 前加**调用方上下文校验位**（当前全内控=直通；预留 `CallerCtx` 参数，桌面 IPC 接线时填 session——本卡只留接口不给实现）
- **A-5（self-id 派生前缀）**：`init(handle, plugin_id)` WIT 扩展——init 传参派生前缀，hello 写死前缀退役（结构性耦合消除）

### 2.4 审计与停手

- 审计三事件：share granted / share read（首调）/ revoke——照 A-2 分级（授权动作=能力面 trap 语义不变）
- **停手**：不做写授权（share 只读）；不做授权链传递（to_plugin 不能转 share）；不做组授权；不做 UI 授权管理面板（SDK/宿主 API 先行）

## 三、DoD

- [ ] share 后 to_plugin 读命中（e2e：两插件，A 分享→B 可读）
- [ ] 未 share 键 B 读拒（namespace-denied 不变）+B 写 A 空间拒（写授权未开）
- [ ] `accept_share=false` 时 share 动作本身拒
- [ ] revoke 后 B 读拒
- [ ] A-5：init 传 plugin_id，hello 前缀派生退役；A-1：CallerCtx 接口位（不实现）
- [ ] 15c 徽章 accept_share 展示；全绿（SOP：先 build wasm[wasip2] 再 test）
