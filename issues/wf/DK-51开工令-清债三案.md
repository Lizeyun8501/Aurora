## 案一（T2 主卡）：OfflineQueue rusqlite 真实化

**任务**：
1. `offline_queue.rs` 内存实现 → rusqlite 持久化：表结构以现有 schema 注释为基（L16/L127：`payload BLOB NOT NULL` + attempts 列），**公开 API 签名不变**（enqueue/dequeue/requeue/dequeue_batch/compress_batch/items/len）
2. 存储路径：接现有数据目录惯例（桌面/move 各自 booted 装配点传入路径；移动端走 app 数据目录）——装配面改动需同步 desktop 与 mobile-ffi 两处
3. 幂等索引持久化：`idempotency_key` 唯一约束落库，去重语义与内存版一致
4. 崩溃安全：enqueue 落库即持久；dequeue 的 attempts 递增需落库（进程中断不丢重试计数）
5. 迁移/兼容：无存量数据需迁移（内存态本就易失），但**测试全量回归**——offline_queue.rs 内既有测试改为对 SQLite 版跑（in-memory SQLite 即可）

**DoD**：
- [ ] 队列落盘：写入→杀进程→重启→items() 仍在（单测模拟 reopen 验证）
- [ ] 幂等键跨进程去重生效
- [ ] 桌面 `cmd_queue_list/drain` 与移动 `queue_list/queue_drain` 功能不回归（CI 五门绿）
- [ ] 接口签名零变更（消费端无感知）

## 案二（T3）：drain 过门——evaluate() 接入生产

**任务**：
