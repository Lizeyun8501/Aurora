## 一、背景

- V1 裁决 A：iroh P2P 为同步底座（WS 三卡转远期）。直连链路已闭环（iroh_transport.rs），**relay 是 NAT 穿透失败时的会合回退面**
- 预探 17418e7 结论：iroh 0.x 的 relay mode API 可行，**本地 `Server::spawn` + relay_mode 注入可零外部依赖验证会合语义**（测试基建已探明）
- relay_mode 档位：Disabled / Default（自动）/ Staging（公共测试网）/ Production

## 二、范围（三块）

### 1. relay mode 配置面
- iroh_transport.rs：relay_mode 可注入（启动配置或 BootedApp 装配参数）
- 缺省 Default（自动回退）；Disabled 档保底语义不变（现行为零回归）

### 2. 会合语义
- 直连失败 → relay 会合路径可用（endpoint 经 relay 中转建立连接）
- relay 不可达 → 显式错误（不静默吞——同步失败须可观测，log 或事件面）

### 3. 测试基建（预探 17418e7 范式）
- 本地 `Server::spawn` 起测试 relay（零外部依赖）
- e2e：两 endpoint 经本地 relay 会合 → 消息到达断言
- Disabled 档回归：现直连测试全绿

## 三、DoD（三条）

1. **relay mode 注入生效**：四档配置可设，Disabled 回归零破坏
2. **本地会合 e2e**：Server::spawn relay → 两端会合 → 消息到达断言（零外部依赖，CI 可跑）
3. **不可达显式错误**：relay 不可达路径有明确错误/日志（不静默）
4. 回归+四门（DESK 以 CI 为准）
