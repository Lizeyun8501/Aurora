## 任务

### 1. 三个示范插件（三种模式模板）

| 插件 | 模式 | 业务逻辑 |
|---|---|---|
| `plugin-hello-guest`（升级） | 分支响应型 | handle-event 按 event 分支（note.created→打 capability+payload 摘要；未知 event→打告警行），init 校验 capability 非空 |
| `plugin-wordcount-guest` | 计算型 | 解析 payload JSON（serde_json，wasm32-wasip2 下编译无碍），统计字数/字符数/行数，结构化输出 `[wordcount] {"chars":N,"words":N,"lines":N}` 单行 JSON 便于测试断言 |
| `plugin-auditlog-guest` | 被动监听型 | handle-event 全量记录 `[audit] ts=<调用计数> event=... payload_len=...`，演示零逻辑旁路插件（最简模板） |

- 三插件同一 `wit/aurora-plugin.wit` 单一事实源（`generate!` path 相对引用，同 d3）
- 输出格式**入文档**：README 或 docs 注明每插件的日志前缀约定——这是第三方开发者的"照抄模板"
- 三插件 guest 侧测试：纯逻辑函数（统计/格式化）单测覆盖——wasm 内业务逻辑用宿主侧单测驱动（逻辑函数与 export 解耦，`cargo test -p` 各插件可跑）

### 2. CI wasm job 矩阵泛化

- `Wasm guest build (DK-14d.3)` → `Wasm guest build`，strategy.matrix 遍历三插件；每插件独立 build+wasm-tools 类型校验（三断言步复用）+独立 artifact
- workspace members 增两新 crate；default-members 纪律与 CI `--exclude` 清单同步扩展

### 3. 端到端集成证明（加分项，可降级）

- 方向：CI 同 job 构建三 guest 后，宿主集成测试加载**真 wasm 产物**跑 install_component→register→invoke 全链（真 wasip2 组件被 wasmtime 36 实例化——超越 d2 wat fixture 的最终证明）
- 实现自由度：e2e 测试对 wasm 缺失容忍（skip+提示构建命令）或 xtask 编排，Bravo 裁决；**若 CI 内编排复杂度超预期，降级为本地脚本+报告披露**，不硬扛
