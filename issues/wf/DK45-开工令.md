## 一、背景与缺口

- DK-42/43 落地了 manifest 级限额（invoke 覆盖链路）与 listing→manifest 传播（签名面外设计）
- DK-43 验收注记缺口：**宿主策略设置入口未落地**——`#[serde(skip)]` 下市场 JSON 拉取后 sandbox 恒为 default，「差异化限额」缺宿主配置点
- **DK-45 前置原语已就绪**（a9b039f，traits/plugin_policy.rs）：`set/plugin_sandbox_policy`（publisher 维度 KV 持久化）+ `apply_sandbox_policy`（安装路径覆盖）——**本卡 = 原语的宿主接线**

## 二、范围（两块）

### 1. tauri commands（策略读写）
- `cmd_list_plugin_policies`：per-publisher 策略列表（读 `plugin_sandbox_policy`，含未配置项的缺省展示）
- `cmd_set_plugin_policy(publisher, limits)`：写入 `set_plugin_sandbox_policy`（原语已封装容错——坏 JSON None、空 publisher 拒绝）
- 装配：BootedApp 无需新字段（原语直收 KV）——lib.rs 注册即可

### 2. settings UI（策略编辑）
- settings 页新增「插件沙箱策略」分组（**WifiOnlyRow 范式**——DK-08 收官组件参照）
- per-publisher 编辑行：deadline ticks + max_memory_bytes 两字段（缺省占位 200/64MiB）
- 编辑即写（cmd_set_plugin_policy），无「保存」按钮（与 wifi_only 即写语义一致）

## 三、DoD（三条）

1. **command 闭环**：set → list roundtrip（tauri 层测试，publisher 隔离+缺省展示正确）
2. **UI 生效**：编辑写入后重开页面值保持（前端状态+KV 持久一致）
3. **安装路径语义锚定**：原语级 e2e——`set_plugin_sandbox_policy(publisher, limits)` → `apply_sandbox_policy(&mut manifest, policy)` → 断言 `manifest.sandbox == limits`；未配置 publisher → manifest.sandbox 保持缺省（**DK-14 市场安装接入即用，本卡锚定语义**）
