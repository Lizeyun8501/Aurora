# Bravo 派发任务书 — R-03 七项功能缺口补卡规划

> 派发对象：Bravo · 生成：2026-09-28 11:40 · 基线 `063637e`（main）
> 优先级：P1（定义即解锁七项功能排期——全流水线下一步的输入）
> 预算：3–5 人日 · **纯规划卡，零实现**

## 〇、任务定位

R-03（九-19 审阅报告补卡）是**规划卡**：V26 需求梳理发现七项常用功能既不在任何 DK 域卡、也无域卡承接——本任务把它们**定义成可派发的域卡**写进 issues/v26_issue清单.md，实现另起排期。**不写任何功能代码。**

## 一、七项功能（审阅报告原文锚点）

| # | 功能 | 域归属建议（Alpha 预裁决，可改判） |
|---|---|---|
| 1 | 每日笔记自动创建 | DK-02 组织结构（与目录树/智能文件夹同域）或独立轻卡 |
| 2 | 单篇笔记加密（Vault） | DK-07 安全域延伸（content_cipher 基建已在——99a8 落库先例） |
| 3 | 任务依赖（GTD 前置/阻塞关系） | DK-06 GTD 域延伸 |
| 4 | 时间追踪（番茄/专注统计） | DK-06 或 DK-15 移动端联动 |
| 5 | 附件预览器（图片/PDF/音视频内联） | DK-09 附件域延伸（AttachmentStore 就绪） |
| 6 | Markdown 源码模式 | DK-05 编辑器域延伸（块↔源码双向） |
| 7 | 自定义主题（用户令牌白名单） | DK-18 设置域（语义令牌基建已有） |

## 二、每张新卡必须包含（清单既有格式对齐）

1. **Labels / Milestone / Estimate**（人日诚实化——含测试与 verify 预算）/ **Blocked by**（真实依赖，禁「依赖全部 UI」）/ **Assignee 建议**（Bravo/Alpha 口径：Rust 数据面 Bravo、UI 裁决面 Alpha）；
2. **任务 3–6 条**（每条可验收，动词开头）；
3. **DoD 2–4 条**（含至少一条可自动化断言口径——verify 脚本或单测）；
4. **与既有基建的关系**：明确复用什么（如 Vault→content_cipher HKDF 每笔记密钥先例；每日笔记→事件总线+投影；主题→语义令牌 tokens）。

## 三、边界与禁改

- **禁改**：既有卡（DK-00~18）的任务/DoD/estimate；R-03 卡本身的 DoD；
- **禁止**：把七项塞进任何一张既有卡的 DoD（每项独立卡——组合爆炸面先例）；估算含糊（必须给出区间下限/上限）；依赖声明指向未建卡；
- **建议**：若某项判断为「不值得做」（如与既有能力重复），给出否决理由并记录——七项不强制全部建卡，但每个决定要有依据。

## 四、DoD（本卡验收门）

1. 七项功能每项：新卡入 v26_issue清单.md **或** 否决记录（理由充分）；
2. 新卡格式与清单既有卡完全一致（grep 字段名核对）；
3. 排期表尾部批次建议更新（第一批/第二批/第三批口径不变）；
4. 交付报告 `bravo-request-R03-补卡规划-交付报告.md`：逐项决定 + 理由 + 新卡清单；
5. CI 五 job 绿（纯 docs 也走 CI——Rustfmt 口径教训：动 .rs 才需逐包 fmt，本卡纯 md 零风险）。

## 五、规约

commit 前缀 `docs(R-03):`；直接推 main；有歧义写 `bravo-request-R03-<主题>.md` 提 Alpha 裁决（如某项域归属争议）。
