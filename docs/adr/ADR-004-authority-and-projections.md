# ADR-004: 权威源三阶段与投影自愈

- 状态：已接受（V26 I3 / DK-01）
- 日期：2026-09-16
- 关联：ADR-003（WritePath）

## 背景

笔记正文存在三个潜在权威：KV 元数据（NoteRecord.content）、
blocks 块索引（SQLite 派生表）、Loro 快照（CRDT 演进目标）。
V25 曾因无权威声明导致读路径各自取数、互相打架。

## 决策

**三阶段权威规则**（每阶段只有一个权威源）：

1. **M1-M3**：`notes` 元数据为权威指针；blocks 为派生索引
2. **观察期**：Loro 快照双写（WritePath persist_doc 先落快照再落
   元数据指针），`verify_dual_write_consistency` 巡检两者一致
3. **终态**：Loro 为正文权威（CRDT 合并语义接管）

**派生失败不阻断主流程**：blocks/搜索索引派生失败仅告警，
主数据已落盘；`rebuild_blocks_derivation` 启动时从权威全量重派生。

**投影自愈**：投影水位线 vs 事件流对比（decide_projection_strategy）——
水位线超前（数据源回退）或落后超阈值（默认 1000 条）→ 全量重建；
否则增量 catch_up。verify 数量不一致同样触发 rebuild。

## 后果

- 正面：读路径唯一（移动端已切读 Loro 快照恢复）；派生损坏自愈；
  观察期有量化巡检工具
- 代价：双写期间存储 ×2（快照 + 元数据）；重建全量扫描有启动成本
- 回滚：三阶段均可回退（快照缺失时读路径自然回落元数据）

## 验证

- 原子事务故障注入 5 场景（tmp 崩溃重做/路径穿越拒绝）
- 对拍 3.5（blocks 清空→重建→双端一致）/ 3.6（策略三段决策）/ 3.7（双写一致）
