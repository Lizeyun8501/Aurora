## 一、总体结论

**代码整体架构方向与 V19 一致**（三层分离、Trait 抽象、本地优先、Rust 核心跨平台共享），
但在 **6 个方面与 V19 原始设计存在差距**。本次提交已完成其中 4 项对齐优化，
其余 2 项列入后续路线。

| # | 审查项 | V19 要求 | 代码现状 | 判定 | 本次处理 |
|---|--------|---------|---------|------|---------|
| 1 | Trait 抽象层 | §28 七大 Trait：SyncTarget / OCREngine / AIProvider / **KVStore** / PluginRuntime / **CryptoProvider** / **SearchBackend** | 8 个 Trait，缺 KVStore、CryptoProvider、SearchBackend；多 CrdtEngine / VectorStore / AgentProtocol | ✗ 部分符合 | ✅ 补齐 3 个缺失 Trait |
| 2 | EventBus | DEF-002 三层通道（High cap100 丢弃 / Medium 有序+持久化 / Low cap1000 批量）+ ARCH-003 event_queue 持久化 + §32 AppEvent/seq 顺序约束 | 单 broadcast 通道，无分级、无持久化、无背压 | ✗ 不符合 | ✅ 新增 `event_bus/layered.rs` |
| 3 | 领域服务组织 | DEF-003 五子层（core_data/knowledge/intelligence/productivity/integration）+ 依赖方向规则 | l3_domain 平铺 10 模块 | ✗ 不符合 | ✅ 新增 `sublayers.rs` 子层视图 |
| 4 | 统一错误类型 | §33 AuroraError：领域变体 + user_message / is_retryable / requires_fallback | 8 个通用变体，无三问方法 | ✗ 部分符合 | ✅ 增强 `Error`（只增不改） |
| 5 | 工程结构 | §27 crates/core + entity + migration + mobile-ffi(UniFFI) | 6 个 aurora-* crate，无 entity/migration/mobile-ffi | ⚠ 命名与拆分不同，理念一致 | ⏳ 列入路线（见 §四） |
| 6 | Trait 异步风格 | §28 全部 `async_trait` | 全部同步签名 | ⚠ 风格差异 | ⏳ 统一迁移列入路线 |

**特别说明 — CryptoProvider 缺失风险**：V19 §10.2.2 强制要求"CryptoEngine 为跨层服务，
所有模块通过 CryptoProvider Trait 访问"。原代码中密码学能力散落在
`l1_infrastructure/crypto.rs` 与 `aurora-security`，无统一 Trait 入口，
导致 L3 模块可直接依赖 ring/aes-gcm 具体实现，违反依赖规则。本次已补齐 Trait 定义，
后续应将 `aurora-security` 重构为该 Trait 的实现并注入各层。

**文档版本冲突备注**：V19 §27 前端写为 Svelte 5，而仓库 V16 spec 及代码均为 React 18。
两版文档不一致，以代码现状（React 18）为准，建议后续修订 V19 文档。

## 二、符合 V19 设计的方面（✓）

1. **三层分离架构**：表现层（apps/desktop Tauri v2 / mobile Capacitor / web WASM）→
   适配层 → Rust 核心层，核心 crate 不依赖任何平台 SDK，符合 §10/§27 设计原则。
2. **Trait 抽象机制**：模块间经 Trait 通信、可运行时替换实现，符合 §1.2/§28 核心理念。
3. **基础设施选型**：Loro CRDT、iroh P2P、SQLite+WAL、Tantivy、Wasmtime、
   AES-256-GCM、Argon2id，与 §10.2.1 选型表一致。
4. **后量子加密**：`aurora-security/post_quantum.rs` 实现 ML-KEM-768 + X25519 双轨，
   符合 §12/§28.6。
5. **领域服务覆盖**：内容编辑、知识网络、GTD、AI、OCR、TodayView、CaptureMatrix、
   导入导出、素材库、系统设置等模块齐备，覆盖 §10.2.2 模块清单。
6. **可观测性**：aurora-observability 覆盖 tracing 日志、prometheus 指标、
   监控告警、诊断排障、灰度回滚（V19 PART VI 运维支柱）。

## 三、本次对齐优化明细

### 3.1 新增 Trait（crates/aurora-core/src/traits/）
- `kv_store.rs` — §28.4 KVStore（get/set/delete/exists/batch_get/batch_set/scan_prefix）
- `crypto_provider.rs` — §28.6 CryptoProvider（AES-256-GCM / Argon2id / ML-KEM-768 KEM / HMAC / algorithm_version），含 Ciphertext、KemPublicKey 等 V19 数据类型
- `search_backend.rs` — §28.7 SearchBackend（search/index_note/batch_index/remove_index/rebuild_index/tokenize），含 SearchOptions/SearchHit/IndexEntry
- `mod.rs` — 更新为 V19 七 Trait 对照表 + V16 扩展 Trait 说明

### 3.2 分层事件总线（crates/aurora-core/src/event_bus/layered.rs）
- `AppEvent` 枚举（§32.1 全部 10 个事件变体）+ `EventChannel` 三通道
- High：broadcast cap 100，lagged 自动丢弃最旧（TodayView 等，允许丢失）
- Medium：mpsc 有序 + `EventQueueStore` 持久化 Trait（生产落 SQLite `event_queue` 表）+ 全局 seq + 水位线 ack
- Low：mpsc cap 1000，满则切换批量补偿模式（幂等）
- 背压：Medium 积压 >50 时 Low 通道延迟 5s（§32.2）
- 崩溃恢复：`replay_unconsumed()` 启动重放（ARCH-003）
- 旧 `EventBus` 保留兼容，新代码走 `LayeredEventBus`

### 3.3 统一错误类型增强（crates/aurora-core/src/lib.rs）
- 新增 V19 §33 变体：Loro / NoteNotFound / InsufficientPermission / Crypto /
  SyncConflict / Plugin / AgentAuth / NlToSqlFailed / Ocr / Config / ModelNotFound
- 新增三问方法：`user_message()`（UI 展示文案）、`is_retryable()`、
  `requires_fallback()`（附 §33.2 降级矩阵注释）
- 全部只增不改，存量代码零影响

### 3.4 五子层视图（crates/aurora-core/src/l3_domain/sublayers.rs）
- core_data / knowledge / intelligence / productivity / integration 五子层 re-export 映射
- 文档化依赖规则：上层可依赖下层、同层经 EventBus 解耦、Crypto 经 CryptoProvider 访问
- 不移动既有文件，零破坏

## 四、遗留路线（未在本次处理）

1. **Trait 异步化统一迁移**：将 11 个 Trait 逐步迁移为 `async_trait`（V19 §28 原始形态），
   需同步改造实现方与调用方，建议独立 PR 分 Trait 推进。
2. **crates/entity + crates/migration**：按 §29 Schema 落 SeaORM/serde 实体与 SQLite 迁移
   （notes/tasks/links/workspaces/event_queue/pending_writes/audit_log/version_snapshots），
   其中 `event_queue`、`pending_writes` 已被分层 EventBus 与原子事务恢复（ARCH-002）依赖。
3. **crates/mobile-ffi（UniFFI）**：移动端 FFI wrapper，与 Capacitor 插件对接。
4. **CryptoProvider 实现落地**：将 aurora-security 重构为 CryptoProvider 的默认实现，
   通过依赖注入替换各层对 ring/aes-gcm 的直接依赖。
5. **EventQueueStore SQLite 实现**：在 migration crate 落地后，
   用 `event_queue` 表实现生产版持久化。
6. **V19 文档修订**：前端框架（Svelte 5 → React 18）与 Trait 清单（8 扩展 Trait）两处
   与代码事实不符，建议回写设计文档。
